## AI 자기 수정 및 점진적 개선 규칙

AI(Antigravity)는 프로젝트를 수행할 때 단발성 코드 작성에 그치지 않고, 다음과 같이 자기 자신과 작성한 코드를 스스로 검토, 수정 및 보완해 나가며 프로젝트를 지속적으로 발전시켜야 합니다.

1. **지속적인 자기 수정 및 검증 (Self-Correction):**
   - 코드를 작성하거나 수정할 때, 스스로 버그나 논리적 허점이 없는지 비판적으로 검토합니다.
   - 테스트 결과나 오류 메시지를 분석하여 잘못된 구현을 신속하게 감지하고, 스스로 올바른 방향으로 코드를 수정해 나갑니다.

2. **점진적 프로젝트 발전 (Incremental Development):**
   - 처음부터 완벽한 설계를 고집하기보다는 작동 가능한 최소 단위의 코드를 검증하고, 이를 토대로 살을 붙여나가는 방식으로 안전하고 견고하게 프로젝트를 빌드합니다.
   - 새로운 요구사항이나 코드 변경이 발생하면, 기존 아키텍처와 스타일 가이드를 준수하면서 리팩토링을 병행하여 프로젝트의 전체적인 코드 품질을 지속적으로 향상시킵니다.

3. **피드백의 능동적 수용 및 개선:**
   - 도구 실행 결과, 컴파일/린트 에러, 사용자의 지적 사항을 단순히 해결하는 것에 그치지 않고, 발생 원인을 근본적으로 분석하여 유사한 실수를 반복하지 않도록 스스로 개선 프로세스를 적용합니다.

## 개발 환경 및 자원 가속화 규칙

1. **GPU 가속화 및 하드웨어 최적화:**
   - 대용량 연산 및 모델 학습의 속도 향상을 위해 PyTorch 및 CUDA를 사용할 수 있는 환경인 경우 적극적으로 GPU 가속을 활용해야 합니다.
2. **프로젝트 독립 가상 환경(venv) 활용:**
   - 개발 및 학습의 패키지 충돌을 방지하기 위해 프로젝트 루트 디렉토리 내에 독립된 Python 가상 환경(`venv`)을 반드시 생성하여 사용해야 합니다.
   - 모든 라이브러리 설치와 실행은 해당 가상 환경의 파이썬 인터프리터를 통해 격리되어 수행되어야 합니다.


## Jupytext 동기화 및 노트북(.ipynb) 편집 규칙

1. **노트북(.ipynb)과 스크립트(.py) 양방향 동기화**:
   - `notebooks/` 폴더 안의 모든 `.ipynb` 파일과 `.py` 파일은 Jupytext에 의해 `percent` 포맷으로 양방향 동기화되도록 설정되어 있습니다 (`notebooks/jupytext.toml` 참조).
2. **AI의 노트북 수정 방식 (중요)**:
   - AI가 직접 `.ipynb` JSON 파일 구조를 편집하면 포맷 오류나 메타데이터 손상 등의 에러가 발생할 확률이 높습니다.
   - 따라서, 사용자가 `.ipynb` 파일을 수정해 달라고 요청하더라도, AI는 직접 `.ipynb`를 편집하지 말고 **페어링된 `.py` 파일을 수정**해야 합니다.
   - **동기화 세부 작동 원칙**: VS Code GUI 에디터에서 파일을 수정하고 저장할 때만 VS Code Jupytext Sync 확장이 자동으로 동작합니다. AI가 파일 편집 도구를 사용하여 파일 시스템에 직접 `.py` 파일을 수정한 경우에는 VS Code 에디터가 실행되지 않으므로 자동 동기화가 되지 않습니다. 따라서 수정 완료 후 반드시 가상 환경 내의 Jupytext CLI 명령(예: `.\venv\Scripts\jupytext --sync <파일명>`)을 직접 실행하여 `.ipynb` 파일에 수정 사항을 강제로 동기화해 주어야 합니다.
